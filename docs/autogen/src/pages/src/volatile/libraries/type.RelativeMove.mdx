# RelativeMove

[Git Source](https://github.com/Uniswap/v4-hooks-public/blob/d1fdaedc28e6c6dcbb5549aac699d42fd2860e52/src/volatile/libraries/RelativeMoveLibrary.sol)

A relative price move, |P_new - P_ref| / P_ref, as an exact ratio with its direction, packed into
one word: bits 0-127 hold the numerator, bits 128-254 the denominator, bit 255 the direction.

<i>

The move itself is never rounded. Each consumer scales it once with `mulUp`, so the only rounding
on the fee path is that final round up. The field widths are headroom, not a cost: masking a stack
word is the same gas at any width. relativeMove needs 96 and 97 bits; test vectors built from
(piE6, 1e6) need up to 117 bits of numerator.

</i>

```solidity
type RelativeMove is uint256;;
```
