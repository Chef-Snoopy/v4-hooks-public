# VolatileFeeCalculation

[Git Source](https://github.com/Uniswap/v4-hooks-public/blob/d1e7b7c8a242702f29d254ce90706aa5f0147cd9/src/volatile/libraries/VolatileFeeCalculation.sol)

**Title:** VolatileFeeCalculation

Pure math for the volatile dynamic-fee algorithm. All `*E6` values are E6 pips; 1e6 = 100%.

<i>

A price move is carried as an exact ratio (RelativeMove) and rounded once, up, where it is scaled
into a fee or a skew step. The Q48 sqrt-ratio intermediate in relativeMove rounds down, which can only
enlarge the move, by at most 2**-47 relative. Both round in favour of LPs.

</i>

## Constants

### ONE_E6

1e6 is 100% in pips format

```solidity
uint256 internal constant ONE_E6 = 1e6;
```

### MAX_HOOK_FEE_E6

Maximum LP fee the hook can charge. Pool.swap combines the LP fee with the protocol fee.
Hook fee of 999_999 compounds to 1e6 for any nonzero protocol fee, whereas 999_998 hits
999_999 for any non-zero protocol fee.

```solidity
uint256 internal constant MAX_HOOK_FEE_E6 = 1e6 - 2;
```

### Q48

Scale for the sqrt-ratio intermediate calculation

```solidity
uint256 internal constant Q48 = 2 ** 48;
```

## Functions

<a id="relativemove-uint160-uint160"></a>

### relativeMove

Relative move between two sqrt prices, as an exact ratio of the reference price.

```solidity
function relativeMove(uint160 sqrtPriceNewX96, uint160 sqrtPriceRefX96) internal pure returns (RelativeMove move);
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| sqrtPriceNewX96 | `uint160` | Current/new sqrt price |
| sqrtPriceRefX96 | `uint160` | Reference sqrt price (denominator) |

**Returns**

| Name | Type | Description |
| ---- | ---- | ----------- |
| move | `RelativeMove` | The ratio \|P_new - P_ref\| / P_ref and whether the price increased |

<a id="newpermandtempfee-volatilefeeconfig-uint24-relativemove"></a>

### newPermAndTempFee

Advances the permanent skew for a new block and prices its one-block backrun charge.

<i>

The side the price moved toward leans (its permanent fee steps up) and the other side is the
backrun side, which carries the temp fee. Baselines follow from `baselineFee`.

</i>

```solidity
function newPermAndTempFee(VolatileFeeConfig memory config, uint24 oldAskPermFeeE6, RelativeMove blockPriceImpact)
        internal
        pure
        returns (uint24 newAskPermFeeE6, uint24 tempFeeE6, bool tempOnBid);
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| config | `VolatileFeeConfig` | Pool's fee config |
| oldAskPermFeeE6 | `uint24` | Previous block's permanent ask-side fee |
| blockPriceImpact | `RelativeMove` | Price impact since the previous block open, with its direction |

**Returns**

| Name | Type | Description |
| ---- | ---- | ----------- |
| newAskPermFeeE6 | `uint24` | New permanent ask-side fee to store |
| tempFeeE6 | `uint24` | Temporary fee for the block, clamped to MAX_HOOK_FEE_E6 |
| tempOnBid | `bool` | True if the temp fee is on the bid side, false if on the ask side |

<a id="baselinefee-volatilefeestate-uint24-bool"></a>

### baselineFee

One side's top-of-block baseline from the stored skew and temp fee.

<i>

The leaning side's baseline is its permanent fee; the backrun side's adds the temp fee. Both
permanent fees are &lt;= maxSkewE6 &lt;= MAX_HOOK_FEE_E6 by the config bounds, so only the temp
side can exceed the ceiling and needs the clamp.

</i>

```solidity
function baselineFee(VolatileFeeState memory state, uint24 restingSpreadE6, bool zeroForOne)
        internal
        pure
        returns (uint24 baselineFeeE6);
```

**Parameters**

| Name | Type | Description |
| ---- | ---- | ----------- |
| state | `VolatileFeeState` | Pool's fee state |
| restingSpreadE6 | `uint24` | Permanent pie: ask + bid fee |
| zeroForOne | `bool` | Swap direction; a sell (true) pays the bid side, a buy (false) the ask side |

**Returns**

| Name | Type | Description |
| ---- | ---- | ----------- |
| baselineFeeE6 | `uint24` | Baseline for that side, clamped to MAX_HOOK_FEE_E6 |
